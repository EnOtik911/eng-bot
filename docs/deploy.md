# Деплой

> Язык этого файла — русский, в отличие от остальной документации в репозитории.
> Причина: это runbook, который выполняет владелец, а не текст, который читает
> ревьюер. Команды, ключи и идентификаторы остаются в оригинале — их надо
> копировать буквально, а не переводить.

> **Про токен бота.** Он равен паролю: кто его знает, тот управляет ботом.
> Не вставляй его в чаты, скриншоты, issue и код. Если всё-таки вставил куда-то,
> откуда это может прочитать кто-то ещё — BotFather → `/revoke` → выбери бота,
> получишь новый токен, старый мгновенно мёртв. Это десять секунд, делай не раздумывая.

Девять шагов. У каждого есть проверка. **Если проверка не прошла — не переходи
к следующему шагу**, иначе ошибка всплывёт через три шага и в другом месте.

Всё воспроизводимо с нуля на чистом Google-аккаунте.

## Что понадобится до начала

- **Личный Google-аккаунт**, не корпоративный Workspace. В Workspace админ может
  запрещать деплой Web App с доступом `Anyone`, а без этого схема не работает вообще.
- **Node.js** — проверь, что есть: `node -v` должно напечатать версию.
  Если нет, поставь с [nodejs.org](https://nodejs.org).
- **clasp** — инструмент выкладки Apps Script. Ставить глобально не надо, и лучше
  не ставить: `npm i -g` часто кладёт бинарник туда, чего нет в `PATH`, и потом
  получаешь `command not found: clasp`. Вместо этого запускай через `npx`, который
  уже есть вместе с Node:

  ```bash
  npx -y @google/clasp@latest login
  ```

  Откроется браузер, разреши доступ. Если в ответ придёт ошибка про Apps Script API —
  открой [script.google.com/home/usersettings](https://script.google.com/home/usersettings)
  и включи переключатель «Google Apps Script API», затем повтори команду.

  Чтобы не писать это целиком каждый раз, заведи алиас **навсегда**, а не на
  текущую сессию — иначе при следующем открытии терминала снова получишь
  `command not found: clasp`:

  ```bash
  echo 'alias clasp="npx -y @google/clasp@latest"' >> ~/.zshrc
  source ~/.zshrc
  ```

  Дальше в инструкции пишется просто `clasp` — это он.
  Проверка: `clasp --version` печатает номер версии.

Ориентировочно 40 минут, из них половина — ожидание BotFather и первых деплоев.

### Открой пустую заметку

Шаги 1–3 выдают четыре значения, а вставлять их надо на шагах 4–6. Буфер обмена
один, поэтому держать их в нём не получится. Открой любую заметку и заведи в ней
заготовку — по ходу будешь заполнять:

```
SHEET_ID   =            # шаг 1
BOT_TOKEN  =            # шаг 2
ALLOWLIST  =            # шаг 2
WEB_APP_URL =           # шаг 5
MINI_APP_URL =          # шаг 6
```

Ни одно из этих значений не попадает в репозиторий и не остаётся в этой заметке
навсегда — после шага 7 заметку можно удалить, всё будет лежать в Script Properties.

## Шаг 1. Таблица

Создай пустую таблицу с названием `Eng_bot DB`.

docs.google.com/spreadsheets/d/1AbC...XyZ/edit

```

**Проверка:** строка примерно из 44 символов, без слэшей.

**Куда:** запиши в заметку как `SHEET_ID`. Вставлять будешь на **шаге 4**,
в Script Properties проекта Apps Script.

## Шаг 2. Бот

В Telegram напиши [@BotFather](https://t.me/BotFather) → `/newbot`. Он спросит имя
и username. Username должен заканчиваться на `bot`.

В ответ придёт токен вида `123456789:AAH...`.

**Проверка:** в терминале сначала положи токен в переменную, потом вызови API.
Так надёжнее, чем подставлять внутрь строки: угловые скобки из шаблона легко
оставить, и тогда придёт `404 Not Found` — потому что `<` и `>` уйдут в URL как есть.

```bash
TOKEN='вставь_сюда_токен_целиком'
curl "https://api.telegram.org/bot$TOKEN/getMe"
```

Кавычки вокруг значения обязательны: в токене есть двоеточие, а `zsh` без кавычек
понимает часть строки как путь и отвечает `no such file or directory`.

Ответ должен содержать `"ok":true` и username твоего бота. Если `"ok":false` —
токен скопирован с лишним пробелом или обрезан.

**Куда:** запиши токен в заметку как `BOT_TOKEN`. Целиком, вместе с двоеточием
и всем, что после него. Вставлять будешь на **шаге 4**.

Заодно узнай свой numeric id: напиши [@userinfobot](https://t.me/userinfobot),
он пришлёт число.

**Куда:** запиши как `ALLOWLIST`. Только цифры, без пробелов. Тоже **шаг 4**.

## Шаг 3. Проект Apps Script

**Зачем этот шаг.** Код бэкенда лежит в репозитории, а исполняется на серверах
Google. Этот шаг создаёт там проект и заливает в него код. Интерфейс Google Таблиц
тут не поможет: таблица — это база данных, а не место, где живёт код.

Есть два пути. Оба дают одинаковый результат, выбирай любой.

### Путь A — через терминал (2 минуты)

**Перед первой командой** — включи программный доступ к своим скриптам:
[script.google.com/home/usersettings](https://script.google.com/home/usersettings) →
переключатель **«Google Apps Script API»** в положение On.

По умолчанию Google запрещает доступ к твоим скриптам через API даже тебе самому.
Это не формальность: скрипты имеют доступ к почте, диску и таблицам, поэтому
включение — осознанное действие. Без него `clasp create` ответит ошибкой со ссылкой
на эту же страницу.

Дальше:

```bash
cd gas
clasp login                                        # если ещё не логинился
clasp create --type standalone --title "Eng_bot"
clasp status                                       # что именно уйдёт наверх
clasp push -f
```

Что происходит по шагам:

| Команда | Что делает | Что появляется |
|---|---|---|
| `clasp login` | OAuth в браузере | `~/.clasprc.json` — твои токены, в домашнем каталоге |
| `clasp create` | Создаёт проект на серверах Google | `.clasp.json` — `scriptId` и `rootDir`, в папке `gas` |
| `clasp status` | Ничего не меняет, только показывает | список файлов к отправке |
| `clasp push -f` | Заливает файлы в проект | 11 `.gs` + манифест в редакторе |

`clasp status` перед первым пушем стоит запускать всегда: если в списке пусто или
там посторонние файлы — значит команда выполняется не из папки `gas`, и это видно
до того, как что-то улетело.

> **Ловушка, которая срабатывает молча.** `clasp create` **перезаписывает**
> локальный `gas/appsscript.json` шаблоном нового проекта: таймзона становится
> `America/New_York`, блок `webapp` исчезает. Ошибки при этом никакой.
> Последствие — триггеры сработают не в тот час, а объявление доступа Web App
> потеряется. Сразу после `clasp create` восстанови файл и только потом пуш:
>
> ```bash
> git checkout gas/appsscript.json
> clasp status          # в списке должен быть appsscript.json
> clasp push -f
> ```
>
> Проверка: `git diff gas/appsscript.json` не показывает изменений, а в манифесте
> стоит `"timeZone": "Europe/Moscow"`.

> **Никогда не запускай `clasp pull` в этом проекте.** В версии 3.x он забирает
> файлы из проекта как `.js`, а не `.gs`, и складывает рядом с исходниками:
> получаются пары `Auth.gs` и `Auth.js` с одинаковым содержимым. Следующий
> `clasp push` отправит обе, и в Apps Script каждая функция окажется объявлена
> дважды. Направление здесь одностороннее: правка в репозитории → `push`.
> На случай промаха `gas/*.js` внесены в `.gitignore`, поэтому в коммит дубликаты
> не попадут — но удалить их с диска придётся руками.

Подробный разбор того, как это устроено — в
[tech-bank/004](../tech-bank/004-clasp-and-apps-script-deployment.md).

Помни, что `clasp` — это алиас из раздела «Что понадобится». Если терминал отвечает
`command not found: clasp`, значит алиас не задан: вернись и выполни строку с `alias`,
либо пиши `npx -y @google/clasp@latest` вместо `clasp` целиком.

`standalone`, а не привязанный к таблице: код обращается к таблице по id, поэтому
скрипт не привязан к одному документу, и источником истины остаётся репозиторий.

Файл `.clasp.json` уже в `.gitignore`, и это принципиально: он содержит адрес
**твоего** личного проекта. Если бы он лежал в репозитории, любой, кто его склонирует,
пушил бы код в твой проект. Публичным остаётся код, приватным — адрес.

**Проверка:** `clasp open-script` открывает редактор, и в нём видны все 11 файлов
`.gs` плюс `appsscript.json`. Если файлов меньше — `clasp push -f` выполнился
не из папки `gas`.

### Путь B — только через браузер, без терминала (5 минут)

Годится, если с clasp не сложилось или просто не хочется возиться. Разницы для
работы системы нет; неудобство только в том, что при следующих правках кода
придётся снова копировать вручную.

1. Открой [script.google.com](https://script.google.com) → **«Новый проект»**.
2. Переименуй проект: клик по названию «Проект без названия» сверху → `Eng_bot`.
3. В редакторе уже есть файл `Код.gs` / `Code.gs` с пустой функцией
   `myFunction`. **Выдели всё его содержимое и удали.**
4. Открой в этом репозитории файл **[dist/all-in-one.gs](../dist/all-in-one.gs)**,
   скопируй его целиком и вставь в редактор. Это все одиннадцать файлов, склеенные
   в один: Apps Script загружает все файлы в одну область видимости, поэтому один
   файл ведёт себя точно так же, как одиннадцать.
5. Сохрани: **Ctrl+S** (или иконка дискеты).

**Проверка:** над областью кода в выпадающем списке функций появились имена —
`selfCheck`, `setupSpreadsheet`, `dailyPing`, `installTriggers` и другие.
Если список пуст или там только `myFunction` — код не вставился или не сохранился.

> Файл `dist/all-in-one.gs` генерируется из `gas/*.gs` командой
> `node test/build-all-in-one.mjs`, и `./test/run-all.sh` падает, если он отстал
> от исходников. То есть содержимое всегда актуальное, руками его править нельзя.

Этот шаг ничего не выдаёт в заметку — он создаёт то место, куда на следующем шаге
лягут значения из шагов 1 и 2.

## Шаг 4. Script Properties

Секреты живут в Script Properties проекта Apps Script. Путь описан по иконкам и
положению, а не по подписям: интерфейс Google может быть на русском, и тогда
английских названий ты не увидишь.

1. Открой редактор проекта: `clasp open-script` из папки `gas`, либо
   [script.google.com](https://script.google.com) → проект `Eng_bot`.
2. В **левой вертикальной панели** четыре иконки. Нужна **нижняя, шестерёнка** —
   «Настройки проекта» / Project Settings.
3. Прокрути страницу до самого низа. Последний блок —
   **«Свойства скрипта»** / Script Properties.
4. **«Добавить свойство скрипта»** / Add script property. Добавь три пары,
   затем **«Сохранить свойства скрипта»** / Save script properties.

> Если шестерёнку нажал, а блока со свойствами нет — значит шаг 3 не выполнен
> и проекта ещё не существует. Свойства принадлежат проекту, а не аккаунту.

Три свойства — **это и есть ответ на вопрос «куда подставлять токен и id таблицы»:**

| Ключ | Значение | Откуда |
|---|---|---|
| `BOT_TOKEN` | `123456789:AAH...` | шаг 2, из заметки |
| `SHEET_ID` | `1AbC...XyZ` | шаг 1, из заметки |
| `ALLOWLIST` | `123456789` | шаг 2, из заметки |

Ещё два свойства, `WEB_APP_URL` и `MINI_APP_URL`, добавишь сюда же на шагах 5 и 7 —
их значения появятся только там.

Значения копируй целиком: токен — вместе с двоеточием и всей частью после него,
id таблицы — без слэшей, allowlist — только цифры, без пробелов.

**Куда эти значения не идут ни при каких обстоятельствах:**

| Место | Почему нет |
|---|---|
| `app/config.js` | Файл публичный, отдаётся браузеру и лежит в репозитории |
| Лист `settings` в таблице | Таблицу можно показывать людям — в этом и смысл |
| Код в `.gs` | `clasp pull` затянет файл в репозиторий вместе с токеном |
| Переменные окружения | В Apps Script их не существует |

Поэтому таблицу и репозиторий можно показывать кому угодно, не потеряв бота.

**Проверка:** вернись в редактор кода (верхняя иконка `< >` в левой панели).
Над областью кода — выпадающий список с именами функций. Выбери в нём `selfCheck`
и нажми **«Выполнить»** / Run слева от списка.

При первом запуске Google попросит разрешения. Это нормально и происходит один раз:
«Проверить доступ» → выбери свой аккаунт → появится предупреждение
«Google не проверил это приложение» / «Google hasn't verified this app» →
**«Дополнительно»** / Advanced (мелкая ссылка слева внизу) →
**«Перейти на страницу Eng_bot (небезопасно)»** / Go to Eng_bot →
**«Разрешить»** / Allow.

Приложение не проверено Google потому, что это твой личный скрипт, а не публикация
в маркетплейсе. Предупреждение здесь ожидаемо.

В журнале выполнения должно быть:

```
BOT_TOKEN: ok (46 chars)
SHEET_ID: ok (44 chars)
ALLOWLIST: ok (9 chars)
spreadsheet: ok — "Eng_bot DB"
tabs: Sheet1
```

Длины могут отличаться. Значения не печатаются никогда — это специально.

Теперь запусти функцию `setupSpreadsheet`.

**Проверка:** открой таблицу. В ней появились листы `cards`, `settings`, `inbox`,
`rejects`, `flush_log`, `review_log_2026`. На листе `settings` десять строк с
ключами и значениями.

## Шаг 5. Деплой Web App

В редакторе **справа сверху** синяя кнопка «Развернуть» / **Deploy** →
**«Новый вариант развертывания»** / New deployment.

В открывшемся окне слева сверху **шестерёнка** возле надписи «Выберите тип» /
Select type → в списке выбери **«Веб-приложение»** / Web app.

Заполни три поля:

| Поле | Значение |
|---|---|
| Описание / Description | любое, например `v1` |
| Запуск от имени / Execute as | **Я** / Me |
| У кого есть доступ / Who has access | **Все** / Anyone |

`Anyone` обязателен: Telegram и браузер обращаются к этому URL анонимно.
Это не дырка — см. проверку ниже.

Нажми «Развернуть» / Deploy. Скопируй **URL веб-приложения** / Web app URL —
он заканчивается на `/exec`.

**Куда:** запиши в заметку как `WEB_APP_URL`, и сразу добавь пятым свойством
в Script Properties (тот же путь, что на шаге 4). Он понадобится дважды: скрипту —
для установки webhook, и тебе — для вставки в `app/config.js` на шаге 6.

**Проверка, часть 1:** открой в браузере `<URL>?action=ping`. Должно вернуться:

```json
{"ok":true,"pong":"2026-08-28T..."}
```

**Проверка, часть 2:** открой `<URL>?action=session`. Должно вернуться:

```json
{"ok":false,"code":"BAD_INIT_DATA"}
```

**Этот отказ и есть критерий успеха.** Endpoint публичный и отказывает всем, у кого
нет подписи от твоего бота. Если вместо этого пришли данные — валидация не работает,
дальше идти нельзя.

## Шаг 6. GitHub Pages

Запушь репозиторий на GitHub, публичным. Бесплатные Pages работают только с
публичного репозитория.

```bash
git remote add origin git@github.com:<твой-логин>/eng-bot.git
git push -u origin main
```

В настройках репозитория: **Settings** → **Pages** → Source: **Deploy from a
branch**, Branch: `main`, папка `/ (root)` → **Save**.

Через 1–2 минуты сайт поднимется по адресу
`https://<логин>.github.io/eng-bot/app/`.

Теперь впиши URL из шага 5 в [app/config.js](../app/config.js):

```javascript
WEB_APP_URL: 'https://script.google.com/macros/s/AKfy.../exec',
```

Закоммить и запушь.

**Проверка:** открой `https://<логин>.github.io/eng-bot/app/` в обычном браузере.
Появится «Загружаю очередь…», затем сообщение про данные запуска. Это правильно:
вне Telegram никакого `initData` нет. Главное — страница загрузилась и стили
применились.

## Шаг 7. Mini App в боте

BotFather → `/mybots` → выбери бота → **Bot Settings** → **Menu Button** →
**Configure menu button**.

Дальше BotFather задаёт **два вопроса подряд**, и второй легко принять за ошибку:

1. *«Send me the URL that will be opened by tapping the menu button»* — пришли
   адрес Pages из шага 6, целиком, вместе с `/app/` на конце.
2. *«Send me the title to be displayed on the button instead of Menu»* — пришли
   **одно короткое слово**, например `Тренажёр`. Это просто подпись кнопки внизу
   чата вместо слова «Menu», ничего технического. До 16 символов.

После второго ответа придёт `Success!`.

**Куда:** добавь этот же URL в Script Properties как `MINI_APP_URL` — без него
ежедневный пинг не сможет прикрепить кнопку запуска.

**Проверка:** открой чат с ботом. Внизу появилась кнопка меню с твоей подписью.
Пока не нажимай — контента ещё нет, он появится на шаге 9.

## Шаг 8. Webhook

В редакторе Apps Script запусти функцию `setWebhook`.

**Проверка:**

```bash
curl "https://api.telegram.org/bot$TOKEN/getWebhookInfo"
```

(если открыл новое окно терминала — задай `TOKEN` заново, переменная не переживает
закрытие окна)

В ответе `url` заполнен, `pending_update_count` равен 0, поля
`last_error_message` нет.

Затем напиши боту `/start` — он должен ответить сообщением с кнопкой запуска.
Если молчит: проверь, что твой id в `ALLOWLIST` совпадает с тем, что прислал
@userinfobot (лишний пробел ломает сверку).

## Шаг 9. Триггеры и первый контент

Запусти функцию `installTriggers`.

Дальше — **единственное действие, которое нельзя выполнить кодом.**

Открой список триггеров: в левой панели **иконка будильника** (третья сверху).
Там два триггера — `dailyPing` и `checkWebhook`. Для **каждого**:

1. Три точки справа от строки триггера.
2. **«Изменить настройки уведомлений»** / Edit notifications.
3. Выбери **«Уведомлять меня сразу»** / Notify me immediately.
4. Сохранить.

Зачем: если триггер упадёт, Google по умолчанию сообщит суточной сводкой на почту,
которую легко пропустить. Именно так бот тихо умирает на неделю. Приложение
дополнительно покажет предупреждение, если триггер не отчитывался больше 36 часов,
но письмо — первая линия.

Теперь контент. В таблице появилось меню **Eng_bot** (если нет — перезагрузи
страницу таблицы):

1. **Eng_bot** → **Засеять стартовый батч** — положит 20 строк в лист `inbox`.
2. **Eng_bot** → **Импортировать батч из inbox**.

**Проверка:** диалог сообщает `Принято единиц: 20`, `Создано карточек: 40`,
`Отклонено: 0`, `Дубликатов: 0`. На листе `cards` — 40 строк: 20 со `state = new`
и `direction = recog`, 20 со `state = locked` и `direction = prod`.

**Финальная проверка:** открой Mini App из бота. Появится карточка, сверху
счётчик «долг 0 · новые 6 · осталось 6». Пройди все шесть, нажми оценки. На экране
«Сессия закрыта» должно быть «Отправлено».

Вернись в таблицу: на листе `review_log_2026` появились 6 строк, а у соответствующих
карточек в `cards` заполнились `stability`, `difficulty`, `due`.

**Вот это и есть работающая система.** Всё, что было до — код, прошедший проверку
в изоляции.

## Что менять дальше без деплоя

Лист `settings`, вступает в силу с следующей сессии:

| Ключ | По умолчанию | На что влияет |
|---|---|---|
| `daily_new_target` | 6 | Новых карточек за сессию |
| `desired_retention` | 0.85 | Самый сильный рычаг на дневную нагрузку. 0.90 даёт примерно на треть больше повторений |
| `session_size_cap` | 120 | Жёсткий потолок одной сессии |
| `leech_threshold` | 5 | Промахов до снятия карточки с оборота |
| `unlock_interval_days` | 21 | Когда открывается производственная карточка |
| `ping_hour` | 8 | Час ежедневного пинга. **После изменения перезапусти `installTriggers`** и снова выставь Notify me immediately |
| `timezone` | Europe/Moscow | Зона для вычисления «сегодня» |

## Повторный деплой после правок в коде

Здесь ловушка, на которой теряют часы:

```bash
cd gas && clasp push -f
```

Если проект создавался путём B (через браузер) — вместо этого перегенерируй бандл
и вставь его заново:

```bash
node test/build-all-in-one.mjs
```

затем скопируй `dist/all-in-one.gs` и замени им содержимое файла в редакторе.

**`clasp push` не меняет то, что отдаёт `/exec`.** Он обновляет только код в
редакторе. Чтобы обновилась работающая версия:

«Развернуть» / **Deploy** → **«Управление развертываниями»** / Manage deployments →
**карандаш** справа у существующего развертывания → в поле «Версия» / Version
выбери **«Новая версия»** / New version → «Развернуть» / Deploy.

URL при этом не меняется — webhook и Mini App переустанавливать не нужно.

Живая проверка после каждого редеплоя:

```bash
curl "$EXEC_URL?action=ping"        # ожидается {"ok":true,...}
curl "$EXEC_URL?action=session"     # ожидается {"ok":false,"code":"BAD_INIT_DATA"}
```

Правки в `app/` живут отдельно: там достаточно `git push`, Pages пересоберёт сам
за минуту. Если браузер отдаёт старую версию — жёсткая перезагрузка, а в Telegram
на iOS иногда требуется закрыть Mini App полностью и открыть заново.

## Если что-то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| Пинг приходит не в тот час | `clasp create` сбросил таймзону в манифесте на `America/New_York` | `git checkout gas/appsscript.json`, затем `clasp push -f` и новая версия развёртывания |
| `command not found: clasp` | Алиас задан только на сессию и не пережил закрытие окна | Добавь алиас в `~/.zshrc`, как в разделе «Что понадобится». Проверка: `clasp --version` |
| В `gas/` появились файлы `.js` рядом с `.gs` | Запускался `clasp pull` | Убедись, что содержимое совпадает (`diff Auth.gs Auth.js`), и удали `.js`. Не пушить до удаления |
| `curl` возвращает `404 Not Found` на `getMe` | В URL остались угловые скобки из шаблона | Токен подставляется без `<` и `>`. Используй переменную `TOKEN`, как в шаге 2 |
| `zsh: no such file or directory: 8976...` | Строка с токеном не в кавычках, `zsh` увидел двоеточие и решил, что это путь | Оберни значение в одинарные кавычки |
| В браузере ошибка CORS при отправке пачки | В запрос попал кастомный заголовок или `Content-Type: application/json` | Apps Script не отвечает на `OPTIONS`, и заголовками на сервере это не лечится. Только «простые» запросы — см. [ADR-03](adr/ADR-03-simple-requests-only.md) |
| `?action=session` возвращает данные без initData | Валидация не работает | Проверь, что `BOT_TOKEN` в Script Properties совпадает с токеном бота, из которого открываешь приложение |
| Приложение пишет «Открой из бота» внутри Telegram | Mini App URL в BotFather не совпадает с адресом Pages | Сверь адреса посимвольно, включая `/app/` на конце |
| `/start` игнорируется | `ALLOWLIST` не совпадает с твоим id | Пробелы и переводы строк ломают сверку |
| Пинг не приходит | Триггер не установлен или упал | `listTriggers` в редакторе; меню таблицы → «Проверить webhook»; посмотри `last_trigger_run` на листе `settings` |
| Импорт отклоняет строки | Формат батча | Причина по каждой строке — на листе `rejects`. Правила: [kb/prompts/batch-generation.md](../kb/prompts/batch-generation.md) |
| Оценки не сохраняются | Пачка не ушла | Открой приложение снова: буфер лежит в `localStorage` и отправляется при следующем запуске. Если не уходит — смотри код ошибки на экране «Сессия закрыта» |
| Неудачный батч засорил базу | — | Найди `source_batch` в листе `cards`, выполни `rollbackBatch('imp_...')` в редакторе. Удалит все карточки этой партии |

## Тесты

```bash
./test/run-all.sh
```

Четыре набора плюс проверка синтаксиса, 40 утверждений, ноль зависимостей —
тесты читают `gas/*.gs` и `app/*.js` напрямую, поэтому у планировщика и схемы
авторизации существует ровно одна копия.

Отдельно, не тест, а измерение:

```bash
node test/load-model.mjs
```

Печатает кривую нагрузки повторений. Дефолт `daily_new_target = 6` взят из его
вывода, а не из формулы.
